<h2 align="center">1.Режимы запуска и компиляции: Сборка, запуск без отладки, запуск с отладкой</h2>
<strong>Сборка</strong> - это процесс подготовки Java программы к использованию. Включает компиляцию исходного кода,
выполнение тестов и упаковку проекта.
Существуют системы автоматической сборки Java проектов, например: Maven и Gradle.
Возьмём за основу Maven. У него существует понятие *жизненный цикл* последовательность этапов, которые
выполняются при сборке Java-проекта
<div align="center">
  <p><code>validate</code></p>
  ↓
  <p><code>compile</code></p>
  ↓
  <p><code>test</code></p>
  ↓
  <p><code>package</code></p>
  ↓
  <p><code>verify</code></p>
  ↓
  <p><code>install</code></p>
  ↓
  <p><code>deploy</code></p>
</div>
<div>
Каждый этап выполняется последовательно и зависимо сверху вниз. Если использовать команду
<code>mvn test</code> - то выполнятся все предыдущие этапы жизни Maven.
Цель Maven - упрощение сборки программы, хотя и без него, можно ручками выполнить всю грязную работу.
Например, блок compile отвечает за компляцию исходного кода Java в байт код (.class), мы можем так же
выполнить это, использовав javac. И ещё один пример - блок test отвечает за прохождение тестов. Если же
мы хотим выполнить это без Maven - придется запускать тесты вручную.
</div>
<div>
<br>
<strong>Запуск без отладки</strong> - это запуск без отладки - обычное выполнение скомпилированной
Java-программы виртуальной машиной JVM без подключения отладчика, с помощью
команды <code>java -cp target/classes Main 1 0 1</code>
Программа выполняется последовательно от начала до завершения. Пользователь не может приостанавливать
выполнение на точках останова и пошагово исследовать состояние программы.
</div>

<br>
<div>
<strong>Отладка</strong> — процесс поиска и устранения ошибок в программе с помощью специального инструмента —
отладчика (Debugger). Зпускется при помощи команды <code>JDB -classpath *указывается путь до скомпилированного класса*Main </code>
<br>
<br>
<strong>Точкa останова</strong> - отметка на определённой строке кода, при достижении которой
выполнение программы приостанавливается - по сути является самой сутью дебагера,ведь мы можем остновится
на опредленном участке кода и посмотреть что происходит с перенными.
Используется команда <code>stop at Class:Line</code>
<br>
<br>
<strong>Режимы выполнения</strong> - мы можем выполнять код построчно, заходить внутрь методов или продолжать выполнение до следующей точки останова
<code>next</code> -Step Over — выполнить следующую строку, не заходя внутрь вызываемого метода. <code>step</code> -Step Into — перейти внутрь вызываемого метода.
<code>step up</code> - 	Step Out — выполнить оставшуюся часть текущего метода и вернуться к месту его вызова.
<code>cont</code> - Continue — продолжить выполнение программы до следующей точки останова или завершения.
<br>
<br>
<strong>Просмотр значений перменных</strong> - Во время остановки программы можно просматривать значения переменных, чтобы понять, какие данные используются в данный момент.
<code>locals;print *переменная, которая нас интересует*; </code>
<br>
<br>
<strong>Стек вызовов</strong> - это структура, которая хранит последовательность вызванных методов, которые ещё не завершили выполнение.
Выполнив команду <code>where</code>, мы сможем посмотреть последовательность методов, через которые программа дошла до текущего места выполнения.
