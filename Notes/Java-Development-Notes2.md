<h2 align="center">1.Этапы компиляции и запуска программы
на Java: исходный код → байт-код (.class) → JVM. Чем это отличается от компиляции в C?</h2>
<strong>Путь Java программы</strong>
Исходный код (.java) → компилятор javac → байт-код (.class) → JVM → выполнение
<code>javac</code> переводит исходный код в байт-код — инструкции для виртуальной машины Java. JVM загружает и проверяет классы,
затем выполняет байт-код: интерпретирует его и может компилировать часто используемые участки в машинный код
с помощью JIT-компилятора.
<strong>Чем это отличается от компиляции в C?</strong>
Компилятор C обычно создаёт исполняемый файл с машинным кодом для конкретной платформы.
Для Java обычно создаётся байт-код, который может запускаться на любой платформе с подходящей JVM.

<h2 align="center">4.Тип enum. Что это? Когда использовать? Примеры.</h2>
enum — тип для фиксированного набора именованных значений.
Используется, когда переменная может принимать только один вариант из заранее известного списка,например:
<br>
<code>
enum Day { MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY}
Day today = Day.MONDAY;
if (today == Day.MONDAY) {
    System.out.println("Начало рабочей недели");
}
</code>
Здесь, мы создали переменную enum, которая содержит опредленные значения, затем создали переменную today и присвоили ей значение MONDAY - из enum <p>
Enum помогает избежать опечаток и произвольных строк, но это не весь опционал, так же значениями enum могут быть : поля, конструкторы и методы.
<h2 align="center">5.Тернарный оператор. Общий синтаксис. Использование в составе выражений и без них.</h2>
Это короткая запись выбора: если условие верно — берём первое значение, иначе — второе <p>
условие ? если_да : если_нет; <p>

<h2 align="center">6.Оператор switch case</h2>
switch проверяет значение и выбирает подходящий вариант действий. Он удобен, когда вариантов несколько
Концепция похожа на if/else, но if/else подходит для разных условий, например >10 или =5, a switch удобен, когда нужно выбрать вариант по точному значению.
<code>
int number = 2;
switch (number) {
    case 1:
        System.out.println("Один");
        break;
    case 2:
        System.out.println("Два");
        break;
    default:
        System.out.println("Другое число");
}
</code>
В случае, если свитч не находит ни один кейс - компилятор попадает в default.
<h2 align="center">7.Области памяти в JVM: стек, куча, Metaspace</h2>
<strong>Стек(Stack)</strong> - это область памяти, которую нам выделяет OC для нашей программы, работет по принципу LIFO (Last In First Out)(Последний пришел
первый ушел). Стек растет вниз, каждый новый элемент получает меньше памяти чем предыдущий (от High memory -> Low memory)
Stack Head - регистр процессора(он всегда идет вниз), он следит за местоположением стека, в самом процессоре есть еще один регистр - stack register (в этом регистре
хранится место где находится stack head) + у процессора есть кеш - он способен загрузить фрейм или весь стек. <p>
В стеке выделяется память для переменной, до того момента, пока она не уйдет из области видимости, такая память крайне быстрая, а после того как  перменная больше
не нужна - стек очищается.<p>
У каждого потока Java свой стек. Обычно его размер +- 1-2 МБ, но точное значение зависит от JVM и системы,
например, в Java на 64-битной Windows значение зависит от доступной виртуальной памяти. <p>
<code>java -Xss(размер(цифра))m (Программа) </code> - такой командой можно определить стек для Java-программый 
<br>
<strong>Куча</strong> - тоже память(расширяемая), которая OC выделяет под нашу программу, но в отличии от стека - память
практически не ограничена. Куча растет вверх. Если оперативная память заканчивается - система выделяет простую память для хранения
данных программы. Такая работа программы заметно медленнее и есть проблемма с фрагментацией.
Максимум можно задать параметром -Xmx, например: <code>java -Xmx(размер(цифра))g (Программа)</code> <p>
В куче находятся созданные программой объекты. Если она заполнится и JVM не сможет освободить достаточно
ненужных объектов, программа получит ошибку нехватки памяти OutOfMemoryError.
<br>
<strong>Итог</strong><p>
Стек используем когда переменные локальные и когда их размер известен при компиляции, а если нам нужен, например вектор
неизвестной величины или какая-то перменная которая переживет стекФрейм - то лучше разместить её на куче, но что касается
JVM - она размещает данные сама.
